# 版本交付与本地清理

用户于 2026-10-25 指定：之后每次完成版本更新，先将代码上传到 GitHub，再删除本地老版本相关文件。

每次交付按以下顺序执行：

1. 完成本次功能、相应检查与构建，更新版本说明。
2. 将本次源码和交付文档推送到 GitHub，确认远端提交与成功构建对应。
3. 下载并核对当前版本的安装包、版本号和校验值，确认本地保留的当前版本可用。
4. 清理本地已被替代的旧 IPA、旧版解压目录、临时构建产物，以及仅服务于旧版交付的重复截图和临时日志。清理前核对绝对路径与内容，只删除确认属于旧版的文件；混有其他文件的目录按文件清理。
5. 向用户报告当前版本安装包位置和实际清理范围。

保留当前版本交付文件、项目源码、Git 历史、版本说明和验收记录、上游源码及许可声明，以及仍需使用的 iLoader、驱动和开发工具。不得将账号数据、签名配置或用户设备上的应用数据当作旧版构建文件删除。

GitHub Actions 产物有保留期限，不能将远端临时产物视为永久备份。清理前必须确认当前版本安装包已经落地；上传或构建失败时不执行旧版清理。
