# SUSTechMobile 橙白设计稿 · 01

这是视觉与交互评审原型，不是正式应用代码。问题是：参考“叶栖小镇”的橙白视觉后，同一套设计语言能否同时服务首页、功能目录和地图？用户已确定视觉方向与交互规则，具体稿件待审阅。

## 查看

直接打开同目录 `OrangeWhite.prototype.html`。单文件，无依赖、网络请求、账号、存储或校园写操作。可选启动方式：

```powershell
python -m http.server 8765 --directory Design
```

- 总览：`http://localhost:8765/OrangeWhite.prototype.html`
- 首页：`?scene=today`
- 预约中心：`?scene=reservations`
- 校园巴士：`?scene=bus`
- 其他已接入视觉的示意页面：`services`、`study`、`account`、`printing`、`card`、`library`。

## 用户已确认的设计约定

- 全 App 统一颜色、字体层级、线性图标、圆角、按钮、内部弹层与动效；重点重排首页、导航、全部二级目录和校车页。其他业务内容页同步换视觉。
- 参考论坛橙白比例：橙色渐变页头、白底、橙色图标与选中态；墨绿、天青作为业务或状态辅助。
- 二级目录同级入口等大，按业务分组，不设主次大小卡。精简无关说明、防御性段落、问候语；功能信息、实际状态与必要操作反馈保留。
- 底部导航使用悬浮圆角栏，保留今天/学习/办事/我的图标和短标签；校车等详情页隐藏主导航。
- 校车显示用户位置。初次纳入自己与附近站台，拖动后停止跟随，定位按钮恢复。定位不可用时校园全图和手动选站。原型只演示定位按钮与地图拖动，未请求真实定位。
- 左上角两个方向最近站台同时展示 ETA，不显示步行距离。1路内环用 ↻，2路外环用 ↺；区间车保留车辆图标和方向。
- 车辆与站台用自定义地图浮卡，一次一张；车辆看下一站/准确匹配的 ETA，站台按线路/方向看最近到达；缺失显示“—”。
- 底部抽屉只放时刻表，默认收起。全部线路分方向分组，支持筛选，正式实现优先滚至当前时间并保留全天可查。
- 计划发车后 0–20 分钟橙色，超过 20 分钟灰色，未来墨绿。原型以 16:10 为示例时间，不等同实际发车。
- 原生系统授权、文件选择和系统分享保留 iOS 交互。

## 本稿覆盖与验证

- 三页同屏总览，另导出首页、预约、地图、车辆浮卡、站点浮卡、展开时刻表、自定义预约面板、办事页和 iPad 目录截图。
- 浏览器实际检查：车辆浮卡、站点各线路到站、时刻表展开/收起、线路筛选、拖动抽屉、预约面板关闭、底栏切换。未发现 JavaScript 异常。
- 所有余额、待办、预约、车辆与时间为示例；地图为 SVG 交互示意，正式应用继续使用 MapKit 与真实 CRA 接口。
- 这是视觉稿：没有实现真实定位、持续跟随、网络刷新、全天完整时刻、真实业务表单或校园写操作。未连接用户账号，也没有生成新 IPA。
- 减少动态效果偏好下关闭过渡；正式 SwiftUI 迁移还需核对 Dynamic Type、VoiceOver、深色模式、对比度及 iPad 窗口适配。

源码与截图单独保留在 `design/orange-white-prototype` 分支，正式实现不直接复用此 HTML。
